# Platform-App Plan — Tauri v2 wrapper for the Business Self-Evaluation Tool

**Status:** Phase A + Phase B complete (2026-09-18) — scaffold, toolchain, icons,
CSP, `sync-app.mjs`, opener plugin, and a successful **Windows release build**
(NSIS installer + MSI, ~10 MB exe; `npm test` green; app launches without
crashing). Phase B passed: **Windows runtime smoke** — a jsdom-based assembly
test suite (32 checks total) plus a real-WebView2 DevTools-protocol probe that
verified the app shell boots on `http://tauri.localhost/`, the wllama ESM
module loads, and the 8.4 MB `.wasm` is served valid over the Tauri asset
protocol. See `docs/smoke-checklist-phase-b.md`. Phases C–F (§8) pending.
**Decision (Sept 17 session):** All platforms + app stores · **Tauri v2** ·
wllama on-device analyzer kept as-is (CPU/WASM fallback, small model) · deep
links / SQLite-backed store / in-app OAuth **deferred**.

**Why Tauri:** the front end is already zero-dependency static HTML/CSS/JS —
Tauri wraps it with a ~10 MB binary instead of Electron's ~150 MB, and its
v2 line ships desktop (Windows/macOS/Linux) **and** mobile (iOS/Android) from
one codebase. The existing web app keeps working unchanged as the web/SWA
distribution; Tauri just adds the "installable app + store" distribution.

> The front end stays the **single source of truth** (`index.html`, `css/`,
> `js/`, `js/vendor/wllama/`). The app wrapper is additive — it must never
> require edits to `app.js`/`data.js` just to keep the *web* distribution
> working. This plan makes `data.js`/`app.js` production-ready for all
> surfaces via a small set of **capability-gated, no-op-when-served-on-web**
> hooks (see §4).

## 4. Front-end integration hooks (capability-gated; web stays untouched)

The app currently calls browser-only APIs that need a shim inside Tauri.
They must be **feature-detected**, so the same files keep working on the web:

| Web API used today | App code | Tauri behaviour | Required change |
|---|---|---|---|
| `window.open(url,"_blank","noopener")` | `app.js` submit flow (MS Forms fallback) | opens a new *webview*, not the browser | register `@tauri-apps/plugin-opener`; its default handler opens external URLs in the **system browser**. If it doesn't intercept automatically, wrap: `const { openUrl } = window.__TAURI_OPENER__ || {}; if (openUrl) await openUrl(url); else window.open(...)`. |
| `navigator.clipboard.writeText` | submit fallback (copy results) | WebView2/WKWebView/Android WebView support it inside a click handler | no change; verified in smoke tests |
| `<a download>` blob | `exportResults()` / `exportHistoryJson()` | WebView2 saves/opens fine; Android WebView may ignore `download` | desktop: OK. Mobile: follow-up approve `plugin-dialog`+`plugin-fs` "Save as", or keep working as-is (results still render on-screen) |
| `localStorage` | `STORAGE_KEY`, `HISTORY_KEY` | persists per webview origin | verify on **every** platform in smoke tests (esp. iOS/Android). Fallback if a platform drops it: migrate to `tauri-plugin-store` behind a hook (deferred unless a platform fails) |
| `window.print()` | Print / Save as PDF | WebView2 ✓ · WKWebView ✓ (iOS Safari print sheet) · Android WebView ≈ | Windows/macOS verify; Android mark as best-effort, recommend .txt export |
| `WebGPU` (`navigator.gpu`) | analyzer (`isWebGpuAvailable`) | **only WebView2 (Windows)** has WebGPU; macOS/Linux/iOS/Android → CPU/WASM | already code-gated; nothing to change. Keep `gpuLayers` unset so it stays portable |
| `<input type=file>` | analyzer upload, history import | works on all four webviews | no change (verify iOS Photo/file picker) |
| `fetch(apiUrl)` (Phase 1 submit) | `submitResults()` | webview fetch to HTTPS is allowed once CSP allows it | when `apiUrl` is set, add it to `connect-src`; SDK fetch from mobile webview over https is fine |

**Analyzer (wllama) — specific risks:**
- The engine is loaded by *dynamic `import()`* of
  `js/vendor/wllama/index.min.js`, then fetches
  `js/vendor/wllama/wasm/wllama.wasm` (relative to `document.baseURI`), then
  pulls the ~1.0 GB GGUF from Hugging Face once and caches it.
- Under the Tauri **asset protocol** (`tauri://localhost` / `https://tauri.localhost`)
  these same-relative fetches should resolve; **must be verified on the first
  `app:dev` run** on Windows and on Android (WebView's module handling is the
  least forgiving).
- **Contingency A (verified simple):** point `ANALYZE.moduleUrl`/`wasmUrl` in a
  platform-specific `data.js` override at asset URLs
  (`convertFileSrc()` / `asset://localhost/…`). Zero Rust changes.
- **Contingency B (if the asset protocol can't serve the wasm):** serve
  `app-dist/` from a tiny in-app HTTP server in `src-tauri/src/lib.rs`
  (e.g., `tiny_http`, one file), set `app.windows[0].url` to
  `http://127.0.0.1:<port>/index.html`, and remove the dev-server dependency.
  Kept as a documented fallback; plain vanilla JS means this is ~30 lines.
- **Mobile model weight:** ~1.0 GB download on a phone is expensive. Do **not**
  vendor weights (project rule). Add a note in the analyzer UI and, if
  approved later, offer a smaller GGUF (e.g. `Qwen2.5-0.5B-Instruct-GGUF` /
  `q4_k_m`) via a `data.js` build-time override for mobile — single config
  change, no code change.

## 5. `scripts/sync-app.mjs` (asset copy — the build glue)

Node-only, no deps, ~40 lines. Copies from repo root into `src-tauri/app-dist/`:

```
index.html
css/            (recursive)
js/             (recursive, incl. js/vendor/wllama/*.js + *.wasm)
```

- Uses `fs.cpSync(src, dest, { recursive: true })` + a small allowlist so
  nothing else (api/, test/, *.md) ever enters the bundle.
- Prints the output size; exits non-zero if `index.html` is missing (fail fast).
- `package.json` scripts:
  ```jsonc
  {
    "app:sync": "node scripts/sync-app.mjs",
    "app:dev": "tauri dev",                     // runs sync + serve.js first
    "app:build": "tauri build",
    "app:android": "tauri android dev",
    "app:android:build": "tauri android build",
    "app:ios": "tauri ios dev",                  // macOS only
    "app:ios:build": "tauri ios build"           // macOS only
  }
  ```

## 6. Skeleton `src-tauri` code

`src/lib.rs` (mobile builds require the lib/bin split):
```rust
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_opener::init())
        .run(tauri::generate_context!())
        .expect("error while running business evaluator");
}
```
`src/main.rs`:
```rust
fn main() { business_evaluator_lib::run() }
```
`capabilities/default.json` grants the renderer the permission set it needs and
nothing more:
```jsonc
{ "identifier": "default", "windows": ["main"],
  "permissions": ["core:default", "opener:default"] }
```
(Add `dialog:default` + `fs:allow-save` only if the Save-As enhancement is
approved — least-privilege gate so nothing is widened pre-emptively.)

Cargo deps: `tauri = { version = "2" }`, `tauri-build = { version = "2" }`,
`tauri-plugin-opener = "2"`. That's **all** — no HTTP server yet.

## 9. Deployment outline (summary of §8 exit gates → release)

- **Internal/distribution:** GitHub Release artifacts from `app-build.yml`
  (NSIS .exe, .dmg, .deb/.rpm/.AppImage) — use `tauri-apps/tauri-action@v0`
  which signs releases and attaches bundles on tag push.
- **Google Play:** signingkey upload keystore in repo secrets →
  `tauri android build` (aab) → upload via `google-play` action or
  Play Console upload. Track `internal → closed → production`.
- **Apple:** store export profile + `.ipa` → `altool`/`notarytool`
  (notarize the DMG for direct download; TestFlight for App Store).
- **Microsoft Store:** MSIX bundle of the NSIS-built exe (self-contained
  licensing) — defer unless asked.
- Rollout stays additive to the existing Azure/SWA path; nothing about
  submission, storage, or identity changes as a result of the wrapper.
